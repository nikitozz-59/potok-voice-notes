# Поток — приложение для часов (Zepp OS)

Голосовая заметка на Amazfit Active: записал → аудио ушло на телефон → телефон
распознал речь и разобрал мысль через LLM → текст приехал обратно на часы.

**Версия 0.5.0** (code 41) · target `Amazfit Active` · Zepp OS 3.0.
Работает в паре с Android-приложением **«Поток» v3.8+** (пагинация `/sync`).
С телефоном старше v3.8 тоже работает — просто без пагинации.

---

## Состав

| Файл | Что |
|---|---|
| `page/index.js` | Часы: главный экран, запись, очередь, список, карточка заметки, SYNC |
| `app-side/index.js` | Side-service в Zepp App: JSON-прокси на `NanoServer` телефона |
| `app-service/index.js` | Фоновый сервис: доотправляет очередь при закрытом экране |
| `widget/index.js` | Secondary-widget на циферблат: статус очереди, заметки |
| `app.json` | appId 1131887, версия 0.5.0 (code 41), `amazfit-active` |
| `app.js` | `BaseApp`, messaging-канал |

Никакого Termux-релея больше нет: «релей» — это `NanoServer` внутри
Android-приложения на `127.0.0.1:8080`, к нему side-service обращается через
`fetch` из Zepp App.

## Как это работает

```
часы (page)            Zepp App (app-side)          телефон (NanoServer)
──────────             ───────────────────          ────────────────────
recorder → файл
base64, куски по 2048  ── STT_CHUNK (await ACK) ──►  накопитель чанков
                                                  ►  POST /transcribe
                                                    декод Opus → WAV
                       ◄──── {accepted:true} ──────  заметка state=PENDING
статус «обработка…»                                 ProcessingQueue: STT → LLM
                                                    → state=DONE

                       ◄──── GET /sync?since=&limit= ──┐
                       ───── {notes, next_since, ──────┘
                              has_more} ──► merge → «готово», аудио удалено
```

Ключевое: телефон отвечает `{accepted}` **мгновенно** — часы не висят на
облаке 2–5 минут, пока идёт распознавание. Транскрипт приезжает отдельно,
через периодический SYNC.

### Пагинация `/sync` (v0.5.0)

Раньше каждый SYNC тянул все заметки целиком. Теперь — страницами:

- курсор `syncCursor` (последний `updated_at` с телефона) хранится в
  `data://notes.json` как поле `syncSince` и переживает перезапуск;
- запрос уходит как `/sync?since=<курсор>&limit=40` (`SYNC_PAGE = 40`);
- пока телефон отвечает `has_more: true` — докачивается следующая страница;
- курсор двигается на `next_since` от телефона;
- merge — через карту по `id` (O(n)), а не `notes.find()` в цикле (было O(n²)).

Курсор идёт по `updated_at`, а не по времени записи: статус собственной
заметки меняется (`queued → pending → done`) при неизменном `ts`, и курсор по
`ts` просто пропустил бы эти обновления.

Со старым телефоном (< v3.8), который не знает `next_since`/`has_more`,
часы откатываются к прежнему полному дампу — не хуже, чем было.

## Установка и сборка

```bash
npm install                                  # первый раз: @zeppos/zml, device-types

npx zeus build --target "Amazfit Active"     # → dist/<appId>-Поток-<ver>-<ts>.zab
npx zeus preview --target "Amazfit Active"   # QR-код для установки через Zepp App
```

**Имя устройства — строго `"Amazfit Active"`.** `amazfit-active` из `app.json`
zeus не примет и уйдёт в интерактивный выбор: получишь ошибку readline.

`zeus build` заканчивается «Notice» про промежуточные продукты и ненулевым
кодом даже при успехе — проверяй появление `.zab` в `dist/`, а не exit code.

Установка: `zeus preview` печатает QR в терминал (живёт ~6 дней) → Zepp App →
сканировать. Либо передать `.zab` вручную.

### Если нужен QR картинкой

Терминальный QR нарисован Unicode-полублоками (`▀▄█`). PowerShell при
перенаправлении вывода **портит кодировку** (двойное перекодирование — вместо
QR получается мусор). Правильный путь — снять вывод байтами через Python:

```bash
python -c "import subprocess; z=r'<путь>\zeus.cmd'; r=subprocess.run([z,'preview','--target','Amazfit Active'],capture_output=True); open('qr_raw.txt','wb').write(r.stdout+r.stderr)"
python -c "s=open('qr_raw.txt','rb').read().decode('utf-8'); lines=[l for l in s.splitlines() if any(c in l for c in '\u2580\u2584\u2588')]; open('qr.txt','w',encoding='utf-8').write('\n'.join(lines))"
python render_qr.py qr.txt qr.png
```

## Экран и управление

```
┌──────────────────────────┐
│ ● Релей: OK · 2 в очереди│  ← точка связи + счётчик
│ ┌──────────────────────┐ │
│ │ 14:32 · готово       │ │
│ │ Купить фильтр для…   │ │
│ └──────────────────────┘ │
│   [ ● Записать ]         │
└──────────────────────────┘
```

Только свайпы, без кнопок навигации:

| Жест | Действие |
|---|---|
| свайп влево | открыть список заметок |
| свайп вправо | закрыть список / выйти из карточки |
| тап по заметке | карточка: текст, чек-лист, «Удалить» / «Повтор» |
| свайп вправо на главном | выход (отдаётся системе) |

Во время записи все свайпы заблокированы — чтобы случайно не потерять запись.

## Статусы

| Статус | Что значит |
|---|---|
| `queued` «в очереди» | записано, ждёт отправки (релей/Zepp App недоступны) |
| `sending` «отправка…» | чанки летят по BLE |
| `pending` «обработка…» | телефон принял, STT/LLM идёт асинхронно |
| `done` «готово» | текст приехал, аудио на часах удалено |
| `error` «ОШИБКА» | терминальная ошибка на телефоне; тап → «Повтор» |

## Поведение

- **Авто-отправка**: после «Стоп» заметка сама уходит, если связь есть.
- **Офлайн-очередь**: нет связи — запись ждёт на часах и уходит при следующем
  PING/SYNC (опрос каждые 45 с) или по кнопке отправки.
- **Фоновый сервис** (`app-service`): доотправляет очередь даже при закрытом
  экране. Разрешение на `device:os.bg_service` спрашивается один раз, флаг
  лежит в `data://bg.flag`.
- **Автостоп 120 с** (`MAX_REC_S`) — защита от обрыва длинных записей.
- **Место**: при свободных < 60 МБ (`MIN_FREE`) запись не начинается с
  предупреждением; при падении места посреди записи — автостоп.
- **Оборванная запись** (приложение закрыли во время записи) сохраняется в
  очередь, не теряется. При старте статус `sending` сбрасывается в `queued`.
- **Аудио** хранится до терминального статуса; после `done` файл удаляется,
  текст остаётся навсегда в `data://notes.json`.

## Палитра

Код палитры B, зарезервированные цвета тема не трогает:

| Роль | Значение |
|---|---|
| акцент / синхронизация | `#2C6FE8` |
| запись | `#00E676` |
| стоп | `#FF1744` |

Иконка — растр с круговой маской, эмодзи только настоящие (Google Emoji),
плашка типа заметки — текстовый маркер, без шрифтовых экзотик.

## Диагностика

| Симптом | Что делать |
|---|---|
| «Релей: нет» | Открыть Zepp App (перезапустить из недавних — side-service кэшируется), проверить, что «Поток» на телефоне запущен и в уведомлении «Релей активен · :8080» |
| Заметка «ОШИБКА» | Тап → причина → «Повтор». `HTTP 503` = на телефоне не задан ключ LLM/STT |
| Старый код в Zepp App | Полностью закрыть Zepp App из недавних и открыть заново |
| Пустая расшифровка | Говорить ближе к часам, меньше фона |
| Синк не двигается | В логах часов строка `sync: done, cursor=…`; если `cursor=0` — телефон старше v3.8 (пагинация не активна, работает полный дамп) |
| QR не сканируется | Истёк срок (~6 дней) — пересобрать `zeus preview` |

Логи: `zeus dev` / `zeus bridge` в консоли разработчика Zepp.

## Ограничения

- Запись только при включённом экране (фоновой записи нет).
- Zepp App должен быть в памяти, иначе side-service не отвечает.
- Записи длиннее 2 минут режутся автостопом (`MAX_REC_S = 120`).
- Поиска, папок и экспорта текста с часов нет — только список и карточка.
